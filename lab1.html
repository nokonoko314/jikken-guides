    OSのインストールとシステム構築

    実施日2026年10月6日（火）
    レポートなし（15:00に経過報告）
    この回でやること旧PCにUbuntu Server 24.04 LTSを入れ、自分のPCからSSHで接続し、Pythonでsinのグラフを出すところまで。余裕があれば公開鍵でのログインも設定する。

    配布資料

    第1回のスライドと実験のガイダンスは、LMSから取得してください。このページは、その内容を自分用に手順化したものです。

    手順の一覧

      使い方

      • 上のバーにユーザ名とサーバのIPを入れると、下のコマンドの黄色い部分が自動で書き換わります（IPはステップ6で調べます）。
      • 終わったステップは右上の「完了」にチェック。入力内容と進み具合はこのブラウザに保存されます。
      • コマンドを打つ場所は、ブロックの左上のラベルで区別しています。
      サーバで直接入力 サーバ（SSH経由・コピペ可） 自分のPCのPowerShell
      コピペできるのはSSH接続後からサーバのPCに直接つないだキーボードでは貼り付けができません。ステップ7までは手で打つ短いコマンドだけにしてあり、ステップ8以降はすべてMobaXtermからコピペできます。
      1

      Ubuntu Serverのイメージを取得

      スライド「本日の作業手順（1）」

      Windows PCで、Ubuntu 24.04 LTSのServer版のISOファイルをダウンロードします。

      1. https://releases.ubuntu.com/24.04/ を開く（スライドの「Previous releases」から辿った先と同じ場所です）
      2. 「Server install image」をクリック
      3. ubuntu-24.04.x-live-server-amd64.iso（約3GB）が保存される

      Desktop版ではなくServer版を選ぶこと。24.04.1でなく24.04.3などの新しい小数点版でも問題ありません（同じ24.04 LTSの更新版です）。

      2

      USBメモリに書き込む

      スライド「本日の作業手順（1）」USBメモリへのイメージの書き込み
      USBの中身はすべて消えます必要なデータが入っていないか確認してから進めてください。
      1. Rufus をダウンロードして起動（インストール不要の「ポータブル版」で可）
      2. 「デバイス」で持ってきたUSBメモリを選ぶ
      3. 「選択」を押して、ステップ1のISOを選ぶ
      4. 他の設定はそのままで「スタート」→ 確認画面はすべて「OK」（ISOイメージモードを推奨）
      5. 状態が「準備完了」になったら終了

      旧PCがUSBから起動しない場合、Rufusの「パーティション構成」をMBRに変えて書き直すと起動できることがあります（古いPCはUEFIではなくBIOS方式の場合があるため）。

      3

      旧PCにインストール

      スライド「本日の作業手順（1）」「2人1組で作業します」

      旧PCにキーボード・マウス・電源・VGAケーブルとLANケーブルをつなぎ、USBを挿して電源を入れます。起動直後にブートメニューのキーを連打し、USBを選びます。

      キーはメーカーで違います。Dell・Lenovoは F12、HPは F9 か Esc、富士通・NECは F12 が多いです。起動画面の下のほうに表示されることもあります。

      「Try or Install Ubuntu Server」を選ぶとインストーラが始まります。↑↓Tabで移動、Enterで決定、Spaceでチェックです。

      画面選ぶもの
      LanguageEnglish（Server版のインストーラに日本語はありません）
      Keyboard configurationLayout：Japanese、Variant：Japanese → Done
      ここで設定すればステップ4は確認だけで済みます
      Type of installationUbuntu Server（そのまま）
      Network configurationLANケーブルがつながっていれば自動でIPが入る（DHCPv4 の横に数字が出る）→ Done
      Proxy / Mirror空欄・そのまま → Done（ミラーのテストが終わるまで少し待つ）
      Guided storage configurationUse an entire disk → Done → 次の確認画面で Continue（ディスクが消去されます）
      Profile configurationYour name / Your servers name / Pick a username / Password を入力。
      usernameとパスワードは必ずメモ（このusernameを上のバーに入れておく）
      Upgrade to Ubuntu ProSkip for now
      SSH configurationInstall OpenSSH server にSpaceでチェック [X] → Done
      Featured server snaps何も選ばず → Done
      Installing system完了したら「Reboot Now」。USBを抜くよう表示されたら抜いて Enter
      4

      ログインとキーボード配列の確認

      スライド「キーボードレイアウトの変更」

      再起動後、login: と出たらステップ3のusernameとパスワードを入力します。パスワードは入力しても画面に何も表示されませんが、正常です。

      キーボードで @ や : を押して、そのとおりの記号が出れば日本語配列になっています。ずれる場合だけ、次を実行します。

      sudo dpkg-reconfigure keyboard-configuration
      （青い設定画面が開く。キーボードの種類 → 配列「Japanese」→ 同じく「Japanese」→ AltGr などは既定のまま Enter。終わるとプロンプトに戻り、何も表示されない）

      出てくる画面では、Generic 105-key PC → Japanese → Japanese → その後はすべてそのまま Enter。終わったら次のコマンドで反映します。

      sudo setupcon
      （何も表示されずにプロンプトに戻れば成功。キー配列がすぐ切り替わる）

      反映されない場合は sudo reboot で再起動。

      6

      IPアドレスを確認

      スライド「IPアドレスについて」
      hostname -I
      192.168.0.142                     ← 最初の数字がサーバのIP（人によって違う）

      表示された数字（例：10.0.5.23）が、このサーバのIPアドレスです。ページ上部のバーに入力してください。以降のコマンドに自動で反映されます。

      この部屋はDHCPで自動割り当てなので、再起動するとIPが変わる可能性があります。SSHがつながらなくなったら、まずこのコマンドで確認し直してください。

      SSHを動かし、ファイアウォールで許可する

      スライド「リモートログイン」

      まずSSHサーバが動いているか確認します。

      sudo systemctl enable --now ssh

      active (running) と出ればOK（qで抜ける）。「Unit ssh.service could not be found」と出たら、インストール時にOpenSSHのチェックが漏れています。次で入れてから、上の2行をもう一度実行します。

      ファイアウォール（ufw）

      必ず allow → enable の順先にenableすると、SSHの通り道（22番ポート）まで閉じてしまいます。
      sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status
      $ sudo ufw allow OpenSSH
Rules updated
Rules updated (v6)
$ sudo ufw enable
Command may disrupt existing ssh connections. Proceed with operation (y|n)? y
Firewall is active and enabled on system startup
$ sudo ufw status
Status: active

To                         Action      From
--                         ------      ----
OpenSSH                    ALLOW       Anywhere
OpenSSH (v6)               ALLOW       Anywhere (v6)

      enableで Proceed with operation (y|n)? と聞かれたら y。statusに OpenSSH ALLOW Anywhere と出ればOKです。

      スライドの「本来はアクセス制限をかけたほうがいい」の発展として、同じネットワーク内からだけ許可する書き方もあります（例：IPが10.0.5.xなら sudo ufw allow from 10.0.5.0/24 to any port 22）。今回は必須ではありません。

      WindowsからSSHで接続

      スライド「リモートログイン」「本日の作業手順（1）」SSHによる接続テスト

      Windows PCを、サーバと同じハブにLANケーブルでつなぎます（無線LANではつながらないことがあります）。

      MobaXtermで接続する（推奨）

      1. MobaXtermを起動 → 左上の「Session」→「SSH」
      2. Remote host にサーバのIP、「Specify username」にチェックしてユーザ名を入力 → OK
      3. 初回は「接続先を信頼するか」を聞かれるので Accept、続けてパスワードを入力

      プロンプトが ユーザ名@サーバ名:~$ になれば成功です。左側に出るファイル一覧がSFTPの画面で、ドラッグ＆ドロップでファイルを送受信できます。

      グラフを描くプログラムを動かす

      スライド「プログラムの実行」「（参考）プロット結果を出力するコード」

      スライドでは、ソースはLMSにアップ済みで、それをSFTPかMobaXtermでアップロードして動かすことになっています。

      A. LMSのファイルをアップロードして実行

      1. LMSからPythonファイルをWindowsにダウンロード
      2. MobaXtermの左側のファイル一覧（SFTP）にドラッグ＆ドロップ

      PowerShellで送る場合は次のとおりです（ダウンロードフォルダにある前提。ファイル名.py を実際の名前に変えてください）。

      cd $env:USERPROFILE\Downloads
scp .\ファイル名.py {{USER}}@{{IP}}:~/
      {{USER}}@{{IP}}'s password:
ファイル名.py                             100%  245    61.3KB/s   00:00

      サーバ側で実行します。

      ls
python3 ファイル名.py
      $ ls
myenv  sample1.py  ファイル名.py
$ python3 ファイル名.py
（そのプログラムの表示が出る）

      MobaXtermはX11転送という機能で、サーバのウィンドウをWindows側に表示できます。sinのグラフのウィンドウが出れば成功です。

      B. ウィンドウが出ない場合：画像で保存して取り出す

      Server版には画面（GUI）がないため、plt.show() では表示されないことがあります。その場合は savefig で画像に保存します。次をまとめてコピーして貼り付ければ、ファイル作成から実行まで一度に終わります。

      cat > ~/plot_sin.py << 'EOF'
import matplotlib.pyplot as plt
import numpy as np
x=np.arange(-10, 10, 0.1)
y=np.sin(x)
plt.plot(x, y)
plt.savefig("sin.png")
print("sin.png を保存しました")
EOF
python3 ~/plot_sin.py
      sin.png を保存しました

      できた sin.png を、MobaXtermの左のファイル一覧からダブルクリック（またはWindowsへドラッグ）して開きます。PowerShellなら次のとおりです。

      scp {{USER}}@{{IP}}:~/sin.png .
start .\sin.png
      sin.png                                   100%   28KB   1.9MB/s   00:00
（写真アプリなどで sin.png が開き、サインのグラフが表示される）

      スライドの参考コードはxの範囲が -10〜10、sample1.py は -1〜1 と違う点にも注意。グラフにするとsin波が約3周期見えます。

      公開鍵でログインできるようにする

      スライド「証明書によるログインにする」「その他にやること」

      鍵はWindows側（ログインする側）で作るのが基本です。秘密鍵が一度もネットワークを通らないため安全です。

      ① 鍵ペアを作る

      ssh-keygen -t ed25519
      Generating public/private ed25519 key pair.
Enter file in which to save the key (C:\Users\あなた/.ssh/id_ed25519):    ← Enter
Enter passphrase (empty for no passphrase):                           ← Enter（または好きな合言葉）
Enter same passphrase again:
Your identification has been saved in C:\Users\あなた/.ssh/id_ed25519
Your public key has been saved in C:\Users\あなた/.ssh/id_ed25519.pub
The key fingerprint is:
SHA256:q0Zf…（毎回違う） あなた@PC名
The key's randomart image is:
+--[ED25519 256]--+
|      …          |
+----[SHA256]-----+
      • 保存場所を聞かれたら、そのまま Enter
      • Overwrite (y/n)? と出たら、すでに鍵があるので n（既存の鍵をそのまま使う）
      • passphrase を聞かれたら、ここで設定（スライドの「秘密鍵にパスワードをかけておくとより安全」）

      作られるのは秘密鍵 id_ed25519（人に渡さない）と公開鍵 id_ed25519.pub（サーバに置く）の2つ。場所は C:\Users\Windowsのユーザ名\.ssh\ です。

      ② 公開鍵をサーバに登録する

      最後にサーバのパスワードを聞かれるので入力します。

      type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh {{USER}}@{{IP}} "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
      {{USER}}@{{IP}}'s password:          ← ここで最後のパスワード入力
（何も表示されずにプロンプトに戻れば、登録できている）

      authorized_keys は「ここに書かれた公開鍵とペアの秘密鍵を持っていれば、ログインを許可する」というリスト。chmod 700/600 で自分以外が触れないようにしないと、sshdが鍵ログインを拒否します。

      ③ 鍵でログインできるか確認

      ssh {{USER}}@{{IP}}
      （パスワードを聞かれずに、次の画面になれば成功）
Welcome to Ubuntu 24.04.3 LTS (GNU/Linux 6.8.0-85-generic x86_64)

 * Documentation:  https://help.ubuntu.com
 * Management:     https://landscape.canonical.com
 * Support:        https://ubuntu.com/pro
…
Last login: Tue Oct 13 13:02:11 2026 from 192.168.0.25
{{USER}}@server:~$

      サーバのパスワードではなく Enter passphrase for key と聞かれる（パスフレーズなしなら何も聞かれずに入れる）なら成功。exit で抜けます。

      MobaXtermでも鍵を使う場合は、セッションを右クリック →「Edit session」→「Advanced SSH settings」→「Use private key」にチェックし、C:\Users\Windowsのユーザ名\.ssh\id_ed25519 を指定します。

      参考：サーバ側で鍵を作った場合

      パスワードログインを無効化する

      スライド「証明書によるログインにする」1つ目
      ステップ12の③が成功してから鍵でログインできない状態で無効化すると、SSHで入れなくなります。また、今つないでいるSSHのウィンドウは閉じずに残し、確認は別ウィンドウで行ってください。

      Ubuntu 24.04では /etc/ssh/sshd_config.d/ の中の設定ファイルが本体より優先され、ファイル名順に先に読んだ設定が勝ちます。そこで、先頭に来る名前（00-）のファイルを作って確実に無効化します。

      echo "PasswordAuthentication no" | sudo tee /etc/ssh/sshd_config.d/00-no-password.conf
sudo sshd -t && sudo systemctl restart ssh
sudo sshd -T | grep -i passwordauthentication
      PasswordAuthentication no
[sudo] password for {{USER}}:
passwordauthentication no          ← 小文字の no が出れば、パスワードでは入れない設定

      最後の行で passwordauthentication no と出れば設定完了です。sshd -t は設定の文法チェックで、エラーがあると再起動しません。

      パスワードで入れないことを確認

      ssh -o PubkeyAuthentication=no {{USER}}@{{IP}}
      {{USER}}@{{IP}}: Permission denied (publickey).          ← これが出れば成功（パスワードでは入れない）

      Permission denied (publickey). と出て、パスワードを聞かれずに拒否されれば成功です。

      元に戻したいとき

      sudo rm /etc/ssh/sshd_config.d/00-no-password.conf
sudo systemctl restart ssh
      （何も表示されない。パスワードでも入れる状態に戻る）

      作業ログを保存してシャットダウン

      スライド「実験上の注意」「今回はここまでです」

      スライドに「作業ログを残すのは基本」とあるので、今日打ったコマンドの履歴を保存して手元に取っておきます。次回やり直すことになっても、これを見ればすぐ再現できます。

      history > ~/command_log.txt
      （何も表示されない。ホームフォルダに command_log.txt ができる）
      scp {{USER}}@{{IP}}:~/command_log.txt .
      command_log.txt                           100% 3150   769.0KB/s   00:00

      最後にシャットダウンします。

      sudo shutdown -h now
      Connection to {{IP}} closed by remote host.
Connection to {{IP}} closed.

      スライドの「shutdown –h now」は、ハイフンがダッシュ記号（–）になっているので、スライドからコピーすると動きません。上のコマンドを使ってください。いきなり電源を切ると、ディスクへの書き込み待ちのデータが失われ、設定ファイルが壊れることがあります。
