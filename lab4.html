    ネットワーク通信

    実施日2026年10月27日（火）

      今回の課題

      スライド「Today's Basic Task」「サーバの要件」「Advanced Task」より。

      区分内容
      基本計算をするサーバと、キーボードから式を送るクライアントを、別々のプログラムとしてソケット通信で作る
      基本式は「整数」「数は2つまで」「演算子と数の間にスペース」（例：45 + 84）。通信はクライアントとサーバが交互に行う（マルチスレッドなし）
      基本サーバは起動中、送られた式と結果を記録し、特定のコマンド（例：HISTORY）で一覧を返す。書式の誤りはクライアントに知らせる
      基本1つのクライアントが接続したまま、何度も送受信できる（複数クライアントの同時接続は不要）
      発展3つ以上の数の計算／かっこや前の結果を変数として使えるプロトコルと書式／データをファイルに保存し、再起動時に読み込む（どれか1つ。ほかの改良もOK）

      スライドの作業手順のとおり、キーボード入力 → 送信だけ・受信だけ → エコーサーバ → 計算サーバの順に、小さく作って動かしながら広げていきます。

      2

      キーボードから文字を読み込む

      スライド「Step 1」標準入力を使うプログラム

      スライドの実行イメージのように、入力した文字をそのまま表示し、また入力を待つプログラムを作ります。

      何か文字を入力してください。
>Hello World
[入力結果] Hello World
>
      使えるもの役割
      Scanner sc = new Scanner(System.in);キーボード（標準入力）から読む準備
      sc.nextLine()Enterまでの1行を文字列で受け取る
      while (sc.hasNextLine()) { … }入力がある間くり返す（Ctrl+Z → Enter で終わる）

      「exit」と打ったら終わる、などの終了の決まりを自分で作っておくと、あとのクライアントにもそのまま使えます。BufferedReader と InputStreamReader を使う方法もあり、通信で使う読み方と同じ形になります。

      3

      送信だけ・受信だけのプログラムを作る

      スライド「Step 2」通信プログラムの基本

      独立した2つのプログラムを作ります。サーバは接続を待って受信したものを表示し、クライアントは接続して1回送信します。この段階では、キーボード入力はなくてもかまいません（スライドより）。

      側使うものしていること
      サーバnew ServerSocket(1102)ポート1102で待ち受けを始める
      サーバserverSocket.accept()クライアントが来るまで待ち、来たらその相手との Socket を返す
      クライアントnew Socket("localhost", 1102)サーバに接続する。2台で試すときは "localhost" を相手のIPにする
      両方socket.getInputStream() を BufferedReader で包む相手から1行ずつ受け取る（readLine()）
      両方socket.getOutputStream() を PrintWriter で包む相手に1行ずつ送る（println()）
      サーバsocket.getInetAddress()接続してきた相手のIP（スライドの「クライアントが接続しました。IPアドレス …」の表示に使う）
      一番多いつまずき：送ったのに届かないPrintWriter は、ためてから送る仕組みです。new PrintWriter(out, true)（自動で送る設定）にするか、flush() を呼ばないと、相手に届きません。また readLine() は改行が来るまで待つので、送る側は print ではなく println を使います。

      日本語を送ると文字化けする場合は、包むときに文字コードを指定します（例：new InputStreamReader(in, StandardCharsets.UTF_8)）。try (…) { }（try-with-resources）で書くと、終わったときにソケットを自動で閉じられます。

      動かす順番

      1. 1つ目のPowerShellでサーバを起動する（「待ち受けを開始しました」が出て止まる）
      2. 2つ目のPowerShellでクライアントを起動する
      3. サーバ側に [受信]Hello World と出れば成功

      先にクライアントを起動すると、待っている相手がいないので Connection refused になります。

      4

      エコーサーバを作る（双方向通信）

      スライド「Step 3」双方向通信

      受け取ったメッセージをそのまま送り返すサーバと、それを受け取れるクライアントにします。手順2のキーボード入力もクライアントに組み込みます。

      [サーバ側]
待ち受けを開始しました。IPアドレス 172.20.21.2 ポート1102
クライアントが接続しました。IPアドレス 172.20.21.10
[受信]Hello World
[送信]Hello World
クライアントが切断しました。

[クライアント側]
サーバに接続しました。IPアドレス 172.20.21.2 ポート1102
文字列を入力してください。
>Hello World
[送信]Hello World
[受信]Hello World
切断しました。
      考えることヒント
      何度も送受信するサーバは「1行受信 → 1行送信」を、クライアントは「入力 → 送信 → 受信 → 表示」をくり返す
      交互に通信する課題の条件「交互に通信（マルチスレッドなし）」のとおり、どちらかが送ったら、もう一方が受け取って返すまで待つ。両方が同時に readLine() で待つと、止まったままになる（デッドロック）
      切断に気づく相手が切断すると、readLine() が null を返す。これをループの終わりの条件にする

      スライドに「エコーサーバが全然作れないぞという場合は早めに呼んでください」とあります。ここで止まったら、早めに先生に相談するのが一番の近道です。

      5

      プロトコル（やり取りの決まり）を設計する

      スライド「プロトコルの設計；現状」「工夫したもの」「Why Design a Protocol?」

      計算サーバに改良する前に、クライアントとサーバがどんな形の文字列を送り合うかを決めます。これがプロトコルです。

      方式スライドの例特徴
      そのまま送る（現状）入力 45 + 84 をそのまま送り、サーバが解釈して 129 を返す作るのは簡単。ただし、返事が答えなのかエラーなのか、クライアントには区別できない
      構造を持たせる（工夫）TERM 3 → OK、84 A 72 D 6 → OK … → ANS 96先頭に「種類」を付けるので、受け取った側が意味を判断できる。拡張しやすく、誤りや攻撃にも強い

      基本課題なら、たとえば「返事の先頭に種類を付ける」だけでも十分に工夫になります。自分の設計を表にしておくと、レポートの図にそのまま使えます。

      クライアント → サーバサーバ → クライアント意味
      （式）（例）ANS …計算結果
      HISTORY？これまでの式と結果の一覧。複数行をどう送り、どこで終わりと分かるようにするか
      書式の誤り？何が悪かったかを伝える
      終了の合図？接続を閉じる

      「？」の部分を自分で決めるのが、この課題の設計の中心です。スライドの「Why Design a Protocol?」は「議論しよう」と問いかけているので、拡張性、通信エラーへの強さ、意図的な攻撃への強さ、などの観点で自分の意見をまとめると、考察に使えます。

      6

      計算サーバに改良する

      スライド「作業手順」実際のサーバに改良／「サーバの要件」

      エコーサーバの「そのまま返す」部分を、「式を解釈して計算し、結果を返す」に置き換えます。スライドに「可能なら正規表現なども使うとよい」とあります。

      やること使えるもの・考え方
      式を分けるline.split(" ") で「数・演算子・数」の3つに分かれるか確かめる
      書式が正しいか調べる正規表現 line.matches("-?\\d+ [+\\-*/] -?\\d+") で「整数 演算子 整数」の形かを一度に判定できる
      文字を数にするInteger.parseInt()。大きすぎる数などで NumberFormatException が出るので、try-catch でエラーとして返す
      計算する演算子で switch する。0で割る場合をエラーとして扱う。整数の割り算は小数点以下が切り捨てになる点も、仕様として決めておく
      記録するサーバに List<String> を用意して「式 = 結果」を追加していく。サーバが起動している間だけ残る（課題の条件どおり）
      HISTORYを返す手順5で決めた形で、記録を送る。0件のときの返事も決めておく

      動作確認では、正しい式だけでなく、わざと間違った入力も試します。どれもエラーとして返れば、「入力エラーを適切に処理する」の要件を満たせます。

      45 + 84
100 / 0
45+84
3.5 * 2
abc
1 + 2 + 3
HISTORY

      「交互に通信」なので、サーバは必ず1回の受信に1回返事をする、という決まりにしておくと、クライアントが返事を待ち続けて固まる事故を防げます。

      7

      2台のPCで通信してみる

      補足

      スライドの実行イメージのように、サーバとクライアントを別のPCで動かします。クライアントの接続先を、サーバを動かすPCのIPにします（上のバーに入れると、下のコマンドに反映されます）。

      Windowsでサーバを動かす場合

      初回の起動で「Windows セキュリティの重要な警告」が出たら、「アクセスを許可する」を押します。相手から届くかは、クライアント側のPCで確かめられます。

      Test-NetConnection {{IP}} -Port 1102
      ComputerName     : {{IP}}
RemoteAddress    : {{IP}}
RemotePort       : 1102
InterfaceAlias   : イーサネット
SourceAddress    : 192.168.0.25
TcpTestSucceeded : True              ← True ならつながる。False ならサーバが動いていないか、ファイアウォール

      TcpTestSucceeded : True なら、サーバまで通信が届いています。False なら、サーバが起動していないか、ファイアウォールで止まっています。

      第1・2回のサーバ（hirox）でサーバを動かす場合

      Ubuntuにも Java を入れれば、サーバ役にできます。前回 ufw を有効にしたので、ポートを開ける必要があります。

      sudo apt install -y openjdk-21-jdk-headless
sudo ufw allow 1102/tcp
java CalcServer.java
      …
Setting up openjdk-21-jdk-headless:amd64 (21.0.8+9~us1-0ubuntu1~24.04.1) ...
$ sudo ufw allow 1102/tcp
Rules updated
Rules updated (v6)
$ java CalcServer.java
（自分で作ったサーバの表示。例：待ち受けを開始しました。ポート1102）

      ファイル名は自分のサーバのクラス名に合わせます。終わったら sudo ufw delete allow 1102/tcp でポートを閉じておくと安全です。第1・2回で学んだ「ファイアウォールで必要なポートだけ開ける」を、自分のプログラムで体験できます。

      発展課題の考え方

      スライド「Advanced Task」
      発展課題考え方の手がかり
      3つ以上の数の計算1 + 2 * 3 のように、掛け算・割り算を先にする必要がある。まず掛け算・割り算を処理してから足し算・引き算をする2段階の方法や、数と演算子のスタックを使う方法がある
      かっこ・前の結果を変数に「データ構造とアルゴリズム」で習う逆ポーランド記法（後置記法）に変換してから計算すると、かっこも扱える。前の結果は「ANS と書いたら直前の答え」「$1 と書いたら1番目の答え」など、書式を自分で決める
      ファイルに保存して再起動時に読み込む計算のたびにファイルの末尾へ1行追記し（Files.writeString(…, StandardOpenOption.APPEND) など）、起動時に Files.readAllLines() で読み込んで記録リストに戻す。ファイルがまだないときの扱いも決める

      どの発展課題も、手順5のプロトコルを広げる必要があります。「基本課題のプロトコルのままでは何が足りなかったか」を書くと、スライドの「なぜプロトコルを設計するのか」への自分なりの答えになり、考察が深くなります。

      うまくいかないとき

      症状原因と対処
      Connection refusedサーバがまだ起動していない、ポート番号が違う。サーバを先に起動する
      Connection timed outIPが違う、別のネットワークにいる、ファイアウォールで止まっている（手順7）
      Address already in use前に起動したサーバがまだ動いている。そのウィンドウで Ctrl+C で止める
      送ったのに相手に何も出ないPrintWriter の自動送信（autoFlush）がない、または println ではなく print を使っている
      両方とも止まったまま動かないサーバもクライアントも受信待ちになっている。どちらが先に送るかの決まりを見直す
      日本語が文字化けする読み書きの文字コードをそろえる（両方 StandardCharsets.UTF_8 を指定）
      2回目の接続ができないサーバが1回のやり取りで終了している。accept() を外側のループに入れると、切断後に次の接続を待てる
