      今回の課題

      スライド「Today's Basic Task」「サーバの要件」「Advanced Task」より（英語のスライドは日本語に直しています）。

      区分内容
      基本計算をするサーバと、キーボードから式を送るクライアントを、別々のプログラムとしてソケット通信で作る
      基本式は「整数」「数は2つまで」「演算子と数の間にスペース」（例：45 + 84）。通信はクライアントとサーバが交互に行う（マルチスレッドなし）
      基本サーバは起動中、送られた式と結果を記録し、特定のコマンド（例：HISTORY）で一覧を返す。書式の誤りはクライアントに知らせる
      基本1つのクライアントが接続したまま、何度も送受信できる（複数クライアントの同時接続は不要）
      発展3つ以上の数の計算／かっこや前の結果を変数として使えるプロトコルと書式／データをファイルに保存し、再起動時に読み込む（どれか1つ。ほかの改良もOK）

      スライドの作業手順のとおり、キーボード入力 → 送信だけ・受信だけ → エコーサーバ → 計算サーバの順に、小さく作って動かしながら広げていきます。

      仕組みを理解する（自分で説明するために）

      補足 経過報告やレポートで、自分の言葉で説明できるようにするためのまとめです。

      通信の流れ（サーバとクライアントで何が起きるか）

      順サーバクライアントひとことで
      1socket() → bind(("", 1102)) → listen()ポート1102で待ち受けを始める
      2accept()（来るまで止まって待つ）socket() → connect((IP, 1102))接続ができると、accept() が相手専用のソケットを返す
      3受信 → 計算 → 送信入力 → 送信 → 受信 → 表示この組を交互にくり返す
      4受信が空（b""）になる → close()close()相手が切断したことに気づいて終わる

      押さえておく4つの考え方

      考え方説明
      IPアドレスとポート番号IPアドレスは「どのPCか」、ポート番号は「そのPCのどのプログラムか」を表す。住所と部屋番号の関係。2つそろって通信相手が1つに決まる
      TCPは区切りのない流れSOCK_STREAM はTCPで、送った順に確実に届くが、メッセージの区切りは守られない。2回送ったものが1回の recv でまとめて届くことがある。だから「改行までが1つのメッセージ」という決まりを自分で作る
      受信は届くまで止まるrecv や readline はデータが来るまで次の行へ進まない（ブロッキング）。両方が受信待ちになると止まったままになるので、「交互に通信」の約束が必要
      文字列とバイト列ソケットで送れるのはバイト列だけ。送る前に encode("utf-8")、受けたら decode("utf-8")。両方でそろえないと日本語が化ける

      送信だけ・受信だけのプログラムを作る

      スライド「Step 2」通信プログラムの基本

      独立した2つのプログラムを作ります。サーバは接続を待って受信したものを表示し、クライアントは接続して1回送信します。この段階では、キーボード入力はなくてもかまいません。クライアントの接続先は、プログラムに直接書いた固定の値でもよいです（スライドより）。

      側使うものしていること
      両方socket.socket(socket.AF_INET, socket.SOCK_STREAM)IPv4・TCPのソケットを作る（引数を省いても同じ）
      サーバbind(("", 1102)) → listen()このPCのポート1102を使うと決め、待ち受けを始める（"" はこのPCのどのIPでも受ける、という意味）
      サーバconn, addr = srv.accept()クライアントが来るまで待ち、来たらその相手専用のソケット conn と、相手の (IP, ポート) を返す。addr[0] がスライドの「クライアントが接続しました。IPアドレス …」に使える
      クライアントconnect(("localhost", 1102))サーバに接続する。2台で試すときは "localhost" を相手のIPにする
      送る側sendall((text + "\n").encode("utf-8"))文字列をバイト列にして全部送る。最後に改行を付けて「ここで1つ」と分かるようにする
      受ける側recv(1024)、または conn.makefile("r", encoding="utf-8") の readline()recv は届いた分（最大1024バイト）をそのまま返す。makefile で作ったファイルの readline() なら、改行までの1行ずつ受け取れる
      一番多いつまずき：区切りがずれるTCPは送った回数どおりに区切って届けてはくれません。手元で試したところ、a\n と b\n を続けて2回送っても、受け手はまとめて受け取ることがありました。recv の1回分を「1つのメッセージ」と思い込まず、改行で区切る決まりにして readline() で読むのが確実です。

      with socket.socket() as s: のように with で書くと、終わったときにソケットが自動で閉じられます。

      動かす順番

      1. 1つ目のPowerShellでサーバを起動する（「待ち受けを開始しました」が出て止まる）
      2. 2つ目のPowerShellでクライアントを起動する
      3. サーバ側に [受信]Hello World と出れば成功

      先にクライアントを起動すると、待っている相手がいないので ConnectionRefusedError: [WinError 10061] になります。

      手本

      # Step 2：受信だけをするサーバ（先に起動する）
import socket

PORT = 1102

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)   # IPv4・TCP のソケットを作る
server.bind(("", PORT))     # このPCのポート1102を使う（"" はこのPCのどのIPでも受ける）
server.listen()             # 待ち受けを始める
ip = socket.gethostbyname(socket.gethostname())
print("待ち受けを開始しました。IPアドレス", ip, "ポート" + str(PORT))

conn, addr = server.accept()    # 接続が来るまで待つ。来たら相手専用のソケット conn ができる
print("クライアントが接続しました。IPアドレス", addr[0])

data = conn.recv(1024)          # 届いたデータ（バイト列）を受け取る
print("[受信]" + data.decode("utf-8"))

conn.close()
server.close()

      考えることヒント
      何度も送受信するサーバは「1行受信 → 1行送信」を、クライアントは「入力 → 送信 → 受信 → 表示」をくり返す
      交互に通信する課題の条件「交互に通信（マルチスレッドなし）」のとおり、どちらかが送ったら、もう一方が受け取って返すまで待つ。両方が同時に受信待ちになると、止まったままになる（デッドロック）
      切断に気づく相手が切断すると、recv は b""、readline() は ""（空）を返す。これをループの終わりの条件にする（手元で確認済み）

      スライドに「エコーサーバが全然作れないぞという場合は早めに呼んでください」とあります。ここで止まったら、早めに先生に相談するのが一番の近道です。

      # Step 3：受け取った1行をそのまま送り返すエコーサーバ
import socket

PORT = 1102

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.bind(("", PORT))
server.listen()
print("待ち受けを開始しました。ポート" + str(PORT))

conn, addr = server.accept()
print("クライアントが接続しました。IPアドレス", addr[0])
reader = conn.makefile("r", encoding="utf-8")   # 1行ずつ読めるようにする

while True:
    line = reader.readline()        # 改行まで（1つのメッセージ）を受け取る
    if line == "":                  # 空なら相手が切断した
        break
    text = line.rstrip("\n")
    print("[受信]" + text)
    conn.sendall((text + "\n").encode("utf-8"))     # 最後に改行を付けて送り返す
    print("[送信]" + text)

print("クライアントが切断しました。")
conn.close()
server.close()

      プロトコル（やり取りの決まり）を設計する

      スライド「プロトコルの設計；現状」「工夫したもの」「Why Design a Protocol?」

      計算サーバに改良する前に、クライアントとサーバがどんな形の文字列を送り合うかを決めます。これがプロトコルです。

      方式スライドの例特徴
      そのまま送る（現状）入力 45 + 84 をそのまま送り、サーバが解釈して 129 を返す作るのは簡単。ただし、返事が答えなのかエラーなのか、クライアントには区別できない。HISTORYのような複数行の返事の終わりも分からない
      構造を持たせる（工夫）TERM 3 → OK、84 A 72 D 6 → OK … → ANS 96先頭に「種類」を付けるので、受け取った側が意味を判断できる。拡張しやすく、誤りや攻撃にも強い

      「工夫したもの」の図の読み方

      送るもの意味
      TERM 3 → OK「これから数を3つ送る」と先に知らせる。サーバは受け取れるかを調べてOKを返す
      84 A 72 D 6 → OK入力 84 + 72 / 6 の記号を英字に置き換えている。Aは足し算（Add）、Dは割り算（Divide）と読める
      ANS 96データがそろったのでサーバが計算する。72 / 6 = 12 を先に計算し、84 + 12 = 96。クライアントはこれを「答えは96です」と人向けに表示する

      この例は数が3つあるので、発展課題（3つ以上の数）の例にもなっています。基本課題なら、たとえば「返事の先頭に種類を付ける」だけでも十分に工夫になります。自分の設計を表にしておくと、レポートの図にそのまま使えます。

      クライアント → サーバサーバ → クライアント意味
      （式）（例）ANS …計算結果
      HISTORY？これまでの式と結果の一覧。複数行をどう送り、どこで終わりと分かるようにするか
      書式の誤り？何が悪かったかを伝える
      終了の合図？接続を閉じる

      「？」の部分を自分で決めるのが、この課題の設計の中心です。スライドの「Why Design a Protocol?」は「議論しよう」と問いかけているので、拡張性、通信エラーへの強さ、意図的な攻撃への強さ、別のプログラムとつながること（相互運用性）、表示とデータを分けられること、などの観点で自分の意見をまとめると、考察に使えます。

      計算サーバに改良する

      スライド「作業手順」実際のサーバに改良／「サーバの要件」

      エコーサーバの「そのまま返す」部分を、「式を解釈して計算し、結果を返す」に置き換えます。スライドに「可能なら正規表現なども使うとよい」とあります。

      やること使えるもの・考え方
      書式が正しいか調べる正規表現 re.fullmatch(r"-?\d+ [+\-*/] -?\d+", line) で「整数 空白 演算子 空白 整数」の形かを一度に判定できる。45+84、3.5 * 2、1 + 2 + 3 は一致しない（手元で確認済み）
      式を分けるa, op, b = line.split(" ") で「数・演算子・数」の3つに分ける
      文字を数にするint()。数でない文字だと ValueError が出るので、try-except でエラーとして返す
      計算する演算子で if を分ける。0で割ると ZeroDivisionError になるので、エラーとして扱う。/ は小数（7 / 2 = 3.5）、// は小さい方へ切り捨て（-7 // 2 = -4）、int(-7 / 2) は0の方へ切り捨て（-3）。どれにするかを仕様として決めておく
      記録するサーバに history = [] を用意して「式 = 結果」を append していく。サーバが起動している間だけ残る（課題の条件どおり）
      HISTORYを返す手順5で決めた形で、記録を送る。0件のときの返事も決めておく
      eval() は使わない受け取った文字列を eval() に渡すと計算は簡単にできますが、計算以外のPythonの命令も実行できてしまいます。「意図的な攻撃に強いプロトコル」（スライド）の反対の例なので、考察の材料にはなりますが、プログラムでは使わないようにします。

      動作確認では、正しい式だけでなく、わざと間違った入力も試します。どれもエラーとして返れば、「入力エラーを適切に処理する」の要件を満たせます。

      「交互に通信」なので、サーバは必ず1回の受信に1回返事をする、という決まりにしておくと、クライアントが返事を待ち続けて固まる事故を防げます。

      手本

      手本のプロトコルは次のとおりです。返事の先頭の語（ANS・ERR・HIST）で、クライアントが返事の種類を見分けます。HISTORY は何件あるか分からないので、先に件数を送り、クライアントはその件数だけ続けて読みます。

      クライアント → サーバサーバ → クライアント意味
      45 + 84ANS 129計算結果
      HISTORYHIST 2 のあとに 45 + 84 = 129 などを2行記録の一覧（件数が先）
      45+84、100 / 0 などERR 理由書式の誤り・0で割った
      （接続を閉じる）—サーバは受信が空になったことで切断に気づき、次の接続を待つ

      コメントの (1)〜(10) は、レポートに載せるサーバのフローチャートの番号に合わせています。割り算は //（小さい方へ切り捨て）なので、-7 / 2 は -4 になります。

      # 計算サーバ（基本課題）
# コメントの (1)〜(10) はレポートの図1（サーバのフローチャート）の番号に対応する
#
# プロトコル（1行が1つのメッセージ。クライアントが1行送ると，サーバが返事をする）
#   式（例 45 + 84）  → ANS 129
#   HISTORY           → HIST 件数 の1行のあと，記録を件数ぶん1行ずつ
#   書式の誤り・0除算 → ERR 理由
import re
import socket

PORT = 1102
PATTERN = r"-?\d+ [+\-*/] -?\d+"    # 整数 空白 演算子 空白 整数

history = []    # 式と結果の記録（サーバが動いている間だけ残る）


def send(conn, text):
    """1行送る（最後に改行を付ける）"""
    conn.sendall((text + "\n").encode("utf-8"))
    print("[送信]" + text)


def calc(expr):
    """式を計算して，返事の1行を作る"""
    # (7) 式の書式は正しい？
    if not re.fullmatch(PATTERN, expr):
        # (8) エラーを返す
        return "ERR 書式が正しくありません（例: 45 + 84）"

    # (9) 計算して記録に追加する
    a, op, b = expr.split(" ")
    a = int(a)
    b = int(b)
    if op == "+":
        ans = a + b
    elif op == "-":
        ans = a - b
    elif op == "*":
        ans = a * b
    else:
        if b == 0:
            return "ERR 0 で割ることはできません"
        ans = a // b        # 整数の割り算（小数点以下は小さい方へ切り捨て）
    history.append(expr + " = " + str(ans))
    return "ANS " + str(ans)


# (1) ポート1102で待ち受けを始める
server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.bind(("", PORT))
server.listen()
print("待ち受けを開始しました。ポート" + str(PORT))

while True:
    # (2) クライアントの接続を待つ
    conn, addr = server.accept()
    print("クライアントが接続しました。IPアドレス", addr[0])
    reader = conn.makefile("r", encoding="utf-8")

    while True:
        # (3) 1行受信する
        line = reader.readline()

        # (4) 切断された？（受け取ったものが空）
        if line == "":
            break
        expr = line.rstrip("\n")
        print("[受信]" + expr)

        # (5) HISTORY？
        if expr == "HISTORY":
            # (6) 記録の一覧を送る（はじめに件数，続けて1件ずつ）
            send(conn, "HIST " + str(len(history)))
            for h in history:
                send(conn, h)
        else:
            # (7)〜(9) は calc の中
            send(conn, calc(expr))

    # (10) 接続を閉じて，次のクライアントを待つ
    print("クライアントが切断しました。")
    conn.close()

    text = input(">")

    # (3) 終了の合図？
    if text == "exit":
        break

    # (4) サーバへ送る
    client.sendall((text + "\n").encode("utf-8"))

    # (5) 返事を受け取って表示する（先頭の語で種類を見分ける）
    reply = reader.readline().rstrip("\n")
    if reply == "":
        print("サーバが切断しました。")
        break
    kind, body = reply.split(" ", 1)
    if kind == "ANS":
        print("答えは " + body + " です")
    elif kind == "ERR":
        print("エラー: " + body)
    elif kind == "HIST":
        count = int(body)
        print("これまでの計算（" + str(count) + " 件）")
        for i in range(count):
            print("  " + reader.readline().rstrip("\n"))

print("切断しました。")

      補足
      質問答えの方向
      サーバを先に起動するのはなぜ？クライアントの connect は、相手が listen で待っていないと断られる（ConnectionRefused）から
      accept() は何を返す？接続してきた相手専用のソケットと、相手のIP・ポート。待ち受け用のソケットとは別物で、送受信は専用の方で行う
      なぜ最後に改行を付ける？TCPはメッセージの区切りを守らないので、改行を「1つのメッセージの終わり」の目印にしている
      なぜ交互に通信する必要がある？受信は届くまで止まって待つので、両方が受信待ちになると動かなくなる。マルチスレッドを使わない条件では、順番を決める必要がある
      切断はどう分かる？相手が閉じると受信が空（b"" や ""）になる。それをループの終わりにしている
      プロトコルを決めると何がよい？返事の種類（答え・エラー・一覧）を区別でき、機能を足しやすく、決めた形以外をはじけるので誤りや攻撃に強い
      HISTORYの終わりはどう判断する？自分のプロトコルで決めた方法で答える（例：最初に件数を送る、最後に終わりの印を送る）
      なぜ eval() を使わなかった？計算以外の命令も実行できてしまい危険だから。決めた形の式だけを受け付けるようにした
