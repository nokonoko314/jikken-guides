      ① 機械学習による画像の分類

      スライド「機械学習による画像の分類」

      配布データ：LMSのzipに、食べ物の画像が50枚（5種類×10枚）入っています。ファイル名は番号だけで、どれが何の料理かは書かれていません。大きさは横512ピクセル前後で、そろっていません。

      py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install opencv-python numpy scikit-learn matplotlib
      段階考え方・ヒント
      1. 正解を用意する課題は「特徴量からクラスタを作る」ことで、答えは配られていません。精度を比べるために、自分で50枚を見て、何の料理かを書いた表（CSV）を先に作っておきます。これは評価のためだけに使い、分類には使いません
      2. 大きさをそろえる特徴量の長さをそろえるため、全部を同じ大きさに縮める（cv2.resize）
      3. 特徴量を作る簡単な順に、色のヒストグラム（第5回の calcHist）、HSVの色ヒストグラム、形や模様の特徴（HOGなど）、学習済みのCNNの中間出力、と試せる
      4. クラスタを作るK-means（sklearn.cluster.KMeans）や階層的クラスタリング（第10回の方法。AgglomerativeClustering）で5つに分ける
      5. 精度を比べるクラスタ番号は「何番が何の料理」と決まっていないので、そのまま正解率は出せない。クラスタごとに一番多い正解の料理を割り当てて正解率を出すか、番号の付け方によらない指標（adjusted_rand_score）を使う。表（混同行列）にすると、どの料理どうしを取り違えたかが見える

      「複数のアルゴリズムを試し精度を比較する」ことが提出物に入っています。特徴量（色だけ／形も）とクラスタリング手法（K-means／階層的）の組み合わせを表にして、どれが何％だったかを並べると、そのまま結果と考察の柱になります。K-meansは最初の中心がランダムなので、random_state を変えて何回か試し、結果のばらつきも見ておきます。

      色のヒストグラムだけだと「赤っぽい料理どうし」が同じクラスタに入りがちです。間違えた画像を並べて、どんな特徴が足りなかったかを書くと、よい考察になります。

      応用課題（学習）：Kaggleの Food-101（スライドのfood41）から、同じ5種類の画像を学習に使い、学習に使っていない画像が何かを当てます。ここでは正解ラベルを使う教師あり学習（ロジスティック回帰、SVM、学習済みCNNの再学習など）になります。データセットは全体で数GBあるので、5種類のフォルダだけを取り出して使います。

      学習用と確認用の画像は必ず分けます。配布の50枚を確認用にすると、基本課題のクラスタリングとの比較もできます。

      つまずいたとき画像フォルダを読み込むとエラーになる

      配布のフォルダには、画像のほかに desktop.ini（Windowsの設定ファイル）が入っています。フォルダの中身を全部読もうとすると、ここで imread が None を返します。拡張子が .jpg のものだけを読むようにします。

      ② ネットワーク機器の性能測定

      スライド「通信プログラムを用いたネットワーク機器の性能測定」

      第4回のソケット通信の応用です。送る側は決まった量のデータを送り続け、受ける側は「受け取ったバイト数 ÷ かかった時間」でスループットを求めます。

      考えることヒント
      どれだけ送るか数KBだと接続の手間ばかりが測れてしまう。数十〜数百MBを送り、1回の測定が数秒以上かかるようにする
      どこで時間を測るか受ける側で、最初のデータが届いてから最後のデータが届くまでを測ると、送る側のバッファの影響を受けにくい
      単位ネットワークの速さはビット毎秒（Mbps）で表すのが普通。バイト数×8 で直す。1000BASE-Tなら上限は1000Mbps
      パケットサイズ1回の write／send で送る大きさを、64B〜64KBくらいで変えて比べる
      TCPとUDPUDPは届いたかどうかの確認がないので、送ったデータに通し番号を入れ、受ける側で欠けた数（損失率）も数える
      機材の比較直結（ケーブル1本）、ハブ1台、スイッチ1台、2台経由…と条件を1つずつ変え、同じ条件で5回ほど測って平均とばらつきを出す

      発展課題の「既存の性能を測定するプログラム」には iperf3 があります（第2回のサーバなら sudo apt install iperf3、Windows版もあります）。自分のプログラムの値と並べ、差がある場合はその理由（バッファの大きさ、Javaの処理の重さなど）を考えると考察になります。

      「ハブ」と「スイッチ」の違い（届いたデータを全部の口に流すか、宛先の口だけに流すか）は、PCを増やして同時に通信させたときに差として表れます。発展課題の「台数を増やす」は、この違いを確かめる実験になります。

      つまずいたときもう1台のPCからつながらない

      Windowsのファイアウォールが、待ち受けているポートへの接続を止めています。初回に出る「アクセスを許可しますか」の画面で「プライベート」を許可するか、測定のあいだだけ許可の設定を追加します。2台のIPが同じネットワーク（例：192.168.1.x どうし）になっているかも、ipconfig で確かめます。Wi‑Fiが有効だとそちらを通ることがあるので、測定中はWi‑Fiを切っておきます。

      ③ 文字画像のWebデータベース

      スライド「文字画像のWebデータベースの構築」「配布画像について」

      配布データ（LMSのzip）：国立国語研究所の資料から、『尚書』巻6の冒頭5ページの画像が、第3種本と第4種本の2種類あります。

      ファイル中身
      dai3syubon/sysy006-001〜005.jpg第3種本の5ページ（縦長、約3000×4200ピクセル）。001が1オ、002が1ウ、003が2オ、004が2ウ、005が3オ
      dai3syubon_pickeddata.txt第3種本のオ（表）のページ（001・003・005）の文字512字分。タブ区切りで、ID・文字・行の名前・割注の印2つ・左上x・左上y・右下x・右下y・幅・高さ
      dai4syubon/sys4006-001〜005.jpg第4種本の5ページ。文字の位置のデータはない（スライドの「全くの手つかず」）
      文字化けした名前の .txt『尚書』巻6の本文の書き起こし（文字化けは「尚書巻6」。zipの文字コードのため）。［ ］の中は割注（小さい文字で2行に書かれた注）
      datapicker/上の pickeddata を元のデータから作ったときのPythonと、元のCSV（全巻分）

      IDの 6-F-01-02-01 は、左から「巻6・オ（F）・1行目・上から2字目・1丁目」です。座標は、そのページの画像そのままのピクセル位置なので、画像から切り出せばその文字が取れます（実際に「尚」の位置で切り出すと「尚」が出ます）。ウ（B）のページ（002・004）の文字は、このファイルには入っていません。

      from PIL import Image
page = Image.open("dai3syubon/sysy006-001.jpg")
x1, y1, x2, y2 = 2669, 518, 2832, 680      # pickeddata の1行目
page.crop((x1, y1, x2, y2)).save("6-F-01-01-01.jpg")
      段階考え方・ヒント
      1. 画像を分割して名前を付けるpickeddata を1行ずつ読み、上の要領で全部切り出す。ファイル名をIDにすると、DBとの対応がとりやすい
      2. DBに入れる第2回のMariaDBに、ID・文字・ページ・行・字の位置・画像ファイル名・どの本か、を持つ表を作る。文字は utf8mb4 の列にする（古い漢字も入るように）。Pythonで INSERT 文を作ってまとめて流すと楽
      3. 検索ページ第2回の個人ページ（public_html）にPHPで作る。文字を入れると、その文字の画像を第3種本・第4種本で並べて表示する。SQLは第2回のサンプルと同じく、プレースホルダ（?）で値を渡す
      4. 本の順に見る「本の見た目で順に比較」は、ページ→行→字の順に並べ替えて表示し、前後の文字へ移れるようにする（ORDER BY でページ・行・字の位置の順）
      5. 第4種本の文字位置のデータがないので、自分で決める必要がある。本文は第3種本と同じはずなので、行と字の並びは対応させられる。画像の縦の列を明るさの合計（投影）で区切る、OpenCVで文字の輪郭を取る（第5回）、それでも難しい部分は手で座標を決める、などを組み合わせる

      5ページ全部の第4種本を切り出すのは時間がかかります。まず1ページ分で検索と比較が動くところまで作り、残りは時間に応じて増やすのが安全です。どこまで自動で切り出せて、どこを手で直したかは、そのまま考察の材料になります。

      応用課題の「画像の比較（一致度）」は、2つの文字画像を同じ大きさにして二値化し、重なる画素の割合を出す、OpenCVの matchTemplate を使う、などの方法があります。「余裕がある人は」にある唐代の写本との比較は、画像をWebで見られますが、使い方の条件を確認してから使ってください。

      つまずいたときdatapick.py を動かすとエラーになる

      datapick.py は、同じフォルダの charac.csv と char_url.csv を読みます。datapicker フォルダに移動してから python datapick.py で実行します。出力は pickeddata.txt です（配布の dai3syubon_pickeddata.txt と同じもの）。

      ファイルの中の ItemID クラスの __repr__ は、存在しない変数 midstring を使っているので、print(elem) のコメントを外すと AttributeError になります。中身を表示したいときは、__init__ で self.idstring = raw と覚えさせ、__repr__ でそれを使うように直します。ほかの巻やページを取り出したいときは、if elem.maki == 6 and elem.fb == "F" … の条件を書き換えます。

      つまずいたときDBに入れた漢字が「?」になる／検索で見つからない

      表や列の文字コードが utf8mb4 になっていないと、一部の漢字が「?」で保存されます。表を作るときに DEFAULT CHARSET=utf8mb4 を付け、PHPの接続（PDOのDSN）にも charset=utf8mb4 を入れます。本文の .txt は先頭にBOM（見えない印）が付いているので、Pythonでは encoding="utf-8-sig" で読むと、1文字目が余計な文字になりません。

      ④ Minecraft Educationでプログラミング教材を作る

      スライド「Minecraft Educationを用いたプログラミング教育システム」
      1. 自分のPCに Minecraft Education を入れる（演習室PCでは動きません）。学校のOffice365（Microsoft）アカウントでサインインする
      2. まず「Hour of Code」のレッスンを通して、ブロックでプログラムを組む流れ（Code Builder、エージェントの動かし方）をつかむ
      3. 教えたいアルゴリズムを1つ決める（ループ、条件分岐、ソートなど）
      4. そのアルゴリズムが「目に見えて」わかるワールドと、使い方を説明する授業資料（スライドか配布資料）を作る
      5. ワールドをエクスポート（.mcworld）して提出する

      ソートなら、高さの違うブロックの柱を並べ、エージェントが2本ずつ比べて入れ替えていく様子を見せる、といった形にすると、ゲームの中で手順が見えます。教材としての評価なので、「誰に」「何を」「どの順で」教えるかを先に決め、授業資料にはねらいと手順、つまずきそうな点を書きます。

      Code Builder では、ブロックのほかに JavaScript や Python でも書けます。ブロックで作ったものを文字のコードに切り替えて見せると、「ブロックとふつうのプログラムの対応」を教える材料になります。

      ⑤ 多人数で使えるチャット（要相談）

      スライド「サーバクライアント型プログラム」

      第4回のエコーサーバを、「1人が送った文を、つながっている全員に配る」形に広げます。

      部分考え方・ヒント
      サーバaccept() で接続を受けるたびに、その人専用のスレッドを作って受信を任せる。メインのスレッドはすぐ次の accept() に戻る
      全員に配るつながっている人の出力先をリストで持ち、受け取った文をそのリスト全員に書き出す。複数のスレッドが同時にリストを触るので、synchronized や CopyOnWriteArrayList で守る
      クライアントキーボード入力を待っている間も、ほかの人の発言が表示されないといけない。受信専用のスレッドを1本作る（これがスライドの「非同期通信」）
      切断相手が抜けたら、例外をつかまえてリストから外す。外さないと、次に配るときに毎回エラーになる

      発展課題のファイル・音声の送受信では、「これは文なのか、ファイルなのか」「何バイト続くのか」を先頭で伝える決まり（プロトコル）が必要になります。第4回で計算サーバのプロトコルを決めたのと同じ考え方で、種類と長さを先に送る形にすると、受ける側が区切りを判断できます。

      ⑥ 通信対戦できるボードゲーム（要相談）

      スライド「Board Game Area を用いた七並べゲームの作成」
      1. Board Game Arena Studio（スライドの参考URL）で開発者アカウントを作る
      2. ハーツのチュートリアルを必ず最後まで行う（スライドで必須とされています）。ゲームの状態の移り変わりを定義する仕組みと、サーバ側（PHP）と画面側（JavaScript）の分担をここでつかむ
      3. ハーツを改良するか、七並べ（難しければUnoのような「順に出す」ゲーム）を新しく作る

      うまくいかないとき（共通）

      症状原因と対処
      zipの中のファイル名が文字化けしているzipを作ったときの文字コードの違い。中身は正しいので、英数字の名前に変えて使う
      ModuleNotFoundError仮想環境が有効になっていない。.\.venv\Scripts\Activate.ps1 をしてから実行
