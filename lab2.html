      前半　自分の公開鍵でログインできるようにする

      鍵は自分のPCで作り、公開鍵だけをサーバに送ります。秘密鍵はネットワークを一度も通りません。パスワードでのログインは、もしものときのために残しておきます。

      自分のPC
      秘密鍵　id_ed25519_ユーザ名手元に置いたまま。人に渡さない
      公開鍵　id_ed25519_ユーザ名.pub
      公開鍵だけ送る
      サーバ
      ~/.ssh/authorized_keys「この鍵の持ち主ならログインを許可する」リスト
      1

      パスワードでログインできるか確認する

      前回スライド「証明書によるログインにする」の続き

      公開鍵を登録するための最初の1回は、パスワードでSSHログインします。まずサーバのIPを確認し、上のバーに入力してください（サーバの前で直接ログインして実行します）。

      hostname -I

      自分のPCから、パスワードでログインできるか試します。

      ssh {{USER}}@{{IP}}
      • 初めて接続するPCでは Are you sure you want to continue connecting (yes/no/[fingerprint])? と出るので、yes と入力
      • サーバでの自分のパスワードを入力して、プロンプトが ユーザ名@サーバ名:~$ になれば確認完了。exit で抜けて次へ
      Permission denied (publickey) と出てパスワードを聞かれない場合

      パスワードログインが無効になっています。サーバの前で、sudoが使えるユーザでログインして次を実行し、最後の行が yes になれば戻っています。

      sudo rm -f /etc/ssh/sshd_config.d/00-no-password.conf
sudo systemctl restart ssh
sudo sshd -T | grep -i passwordauthentication

      00-no-password.conf 以外の方法（/etc/ssh/sshd_config の直接編集など）で無効にした場合は、その行を PasswordAuthentication yes に戻してから sudo systemctl restart ssh を実行します。

      2

      自分のPCで鍵ペアを作る

      前回スライド「証明書によるログインにする」
      mkdir $env:USERPROFILE\.ssh -Force
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\id_ed25519_{{USER}}
      表示操作
      Enter passphrase (empty for no passphrase):秘密鍵のパスフレーズを入力して Enter。なしなら Enter だけ
      Enter same passphrase again:1回目と同じものを入力して Enter
      Overwrite (y/n)?同じ名前の鍵がすでにある。作り直すなら y、今ある鍵を使うなら n

      入力中は何も表示されませんが、正常です。最後に四角い模様（randomart）が出れば完成です。できたファイルを確認します。

      dir $env:USERPROFILE\.ssh

      id_ed25519_ユーザ名（秘密鍵）と id_ed25519_ユーザ名.pub（公開鍵）の2つがあればOKです。

      パスフレーズはスライドの「秘密鍵にパスワードをかけておくとより安全」にあたります。秘密鍵のファイルが盗まれても、パスフレーズが分からなければ使えません。-f で名前を指定しているので、このPCにある他の鍵を上書きすることはありません。

      3

      公開鍵をサーバに登録する

      前回スライド「証明書によるログインにする」

      公開鍵の中身をSSHでサーバに送り、自分の authorized_keys に追記します。この1行で完了します。

      type $env:USERPROFILE\.ssh\id_ed25519_{{USER}}.pub | ssh {{USER}}@{{IP}} "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
      • 初めて接続するPCでは Are you sure you want to continue connecting (yes/no/[fingerprint])? と出るので、yes と入力
      • 聞かれるのはサーバでの自分のパスワード（鍵のパスフレーズではありません）
      • 何も表示されずにプロンプトに戻れば成功
      部分していること
      type ….pub自分のPCにある公開鍵の中身を読み出す
      | ssh …読み出した中身を、SSHでサーバへ送る
      mkdir -p ~/.sshサーバに .ssh フォルダがなければ作る
      cat >> ~/.ssh/authorized_keys受け取った公開鍵を、ファイルの末尾に追記する
      chmod 700 / 600自分以外が読み書きできないようにする。権限が緩いと、sshdが鍵ログインを拒否する
      手でコピー＆ペーストして登録する場合

      結果は上の1行と同じです。まず自分のPCで公開鍵を表示し、出てきた1行（ssh-ed25519 AAAA…）をすべてコピーします。

      type $env:USERPROFILE\.ssh\id_ed25519_{{USER}}.pub

      パスワードでサーバに入り、ファイルを開いて貼り付け、保存します（Ctrl+O → Enter → Ctrl+X）。

      mkdir -p ~/.ssh
nano ~/.ssh/authorized_keys
      chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
      4

      鍵だけでログインできるか確認する

      前回スライド「証明書によるログインにする」

      パスワードを使えないようにしたうえで接続します。これで入れれば、鍵での認証が確実に成功していることになります。

      ssh -o PasswordAuthentication=no -i $env:USERPROFILE\.ssh\id_ed25519_{{USER}} {{USER}}@{{IP}}
      • パスフレーズを付けた場合は Enter passphrase for key と聞かれる（サーバのパスワードではない）
      • パスフレーズなしの場合は、何も聞かれずにログインできる
      • プロンプトが ユーザ名@サーバ名:~$ になれば成功

      ログインできたら、登録された公開鍵を確認してから抜けます。

      cat ~/.ssh/authorized_keys
ls -la ~/.ssh
exit

      ls -la の結果で、.（.sshフォルダ自身）が drwx------、authorized_keys が -rw------- なら権限も正しく設定されています。Permission denied (publickey) と出た場合は、ページ下の「うまくいかないとき」を見てください。

      5

      パスワードでも入れることを確認する

      安全のための確認

      今度は逆に、鍵を使わずに接続します。パスワードを聞かれてログインできれば、もしものときの入口が残っていることになります。

      ssh -o PubkeyAuthentication=no {{USER}}@{{IP}}
      exit
      これで「鍵でもパスワードでも入れる」状態です今日はパスワードログインを残したまま進めます。無効にするのは、鍵での作業に慣れて、秘密鍵のバックアップもとってからで大丈夫です（方法はステップ6の下にあります）。
      6

      接続コマンドを短くする（任意）

      手順書オリジナル

      毎回 -i … やIPを打つのは大変なので、自分のPCの .ssh\config に接続先を登録しておきます。

      @"

Host lab
    HostName {{IP}}
    User {{USER}}
    IdentityFile ~/.ssh/id_ed25519_{{USER}}
"@ | Add-Content -Encoding ascii $env:USERPROFILE\.ssh\config

      これで、接続もファイル送信も lab だけで済みます。

      ssh lab

      IPが変わったら、notepad $env:USERPROFILE\.ssh\config で開いて HostName の行を書き換えてください。以下の手順は、このステップを飛ばしても動くように、すべて省略しない形で書いています。

      参考：後でパスワードログインを無効にするとき

      鍵で入れることを確認した状態で、サーバで実行します。作業中のSSHは閉じずに、確認は別のウィンドウで行ってください。

      echo "PasswordAuthentication no" | sudo tee /etc/ssh/sshd_config.d/00-no-password.conf
sudo sshd -t && sudo systemctl restart ssh
sudo sshd -T | grep -i passwordauthentication

      この設定は、相方を含むサーバの全ユーザに効きます。全員が鍵を登録してから行ってください。

      後半　Webサーバとデータベースを動かす

      ブラウザでボタンを押すと、押した時刻と押した人のIPアドレスがデータベースに記録され、一覧で表示される仕組みを作ります。そのために3つのソフトを入れます。

      ソフト役割
      Apache（アパッチ）Webサーバ。ブラウザからのリクエストを受け取り、ページを返す
      PHPサーバ側で動くプログラム言語。リクエストのたびにページを作る
      MySQLデータベース。データを表（テーブル）の形で保存する

      Linux・Apache・MySQL・PHPの頭文字をとって LAMP と呼ばれる、Webシステムの定番の構成です。

      SSHで入り、sudoが使えるか確認する

      第2回「サーバ構築」
      ssh -i $env:USERPROFILE\.ssh\id_ed25519_{{USER}} {{USER}}@{{IP}}
      groups

      結果に sudo があれば、以降の手順はすべてこのユーザで進められます。ない場合は、sudoが使えるユーザ（インストール時に作ったユーザ）で次を実行してもらい、一度 exit して入り直します。

      sudo usermod -aG sudo {{USER}}

      Apache・PHP・MySQLをインストールする

      第2回「ソフトウェアの設定」
      sudo apt update
sudo apt install -y apache2 php libapache2-mod-php php-mysql mysql-server
      パッケージ中身
      apache2Webサーバ本体
      phpPHP本体
      libapache2-mod-phpApacheがPHPを実行できるようにする部品。ないとPHPのコードがそのまま表示される
      php-mysqlPHPからMySQLに接続するための部品（PDOのドライバ）。ないと could not find driver
      mysql-serverデータベース本体（MySQL 8）

      数分かかります。終わったら、3つが動いているか確認します。

      systemctl is-active apache2 mysql
php -v

      active が2行と、PHPのバージョン（PHP 8.3.x）が出ればOKです。

      9

      ファイアウォールでWebを許可し、表示を確認する

      前回「リモートログイン」と同じ考え方

      前回ufwを有効にしたので、Webが使う80番ポートを開けないとブラウザからつながりません。

      sudo ufw allow 'Apache'
sudo ufw status

      OpenSSH に加えて Apache ALLOW Anywhere が出ればOKです。自分のPCのブラウザで次を開きます。

      http://{{IP}}/

      「Apache2 Default Page」と書かれたページが出れば、Webサーバが動いています。

      このページの実体は、サーバの /var/www/html/index.html です。Apacheは、/var/www/html の中のファイルをブラウザに返します（ドキュメントルート）。

      PHPが動くか確認する

      第2回「ソフトウェアの設定」

      PHPの設定情報を表示するページを一時的に作ります。

      echo '<?php phpinfo();' | sudo tee /var/www/html/info.php
      http://{{IP}}/info.php

      紫色の表のページが出ればPHPは動いています。ページ内を Ctrl+F で pdo_mysql と検索し、見つかれば、PHPからMySQLに接続する準備もできています。

      確認が終わったら削除します（ステップ16）このページはサーバの構成を誰にでも見せてしまうので、公開しているサーバに残してはいけません。
      11

      データベースと表を作る

      db_sample / dateadd.php のコメント

      配布の dateadd.php のコメントに書かれている準備を行います。MySQLに管理者として入ります。

      sudo mysql

      プロンプトが mysql> に変わったら、次をまとめて貼り付けます。

      CREATE DATABASE updatetime;
CREATE USER 'ktajima'@'localhost' IDENTIFIED BY 'password';
GRANT ALL ON updatetime.* TO 'ktajima'@'localhost';
CREATE TABLE updatetime.clickedtable (time DATETIME NOT NULL, ip TEXT NOT NULL);
SHOW TABLES FROM updatetime;
exit

      clickedtable と表示されればOKです。

      SQLしていること
      CREATE DATABASEupdatetime というデータベース（表を入れる箱）を作る
      CREATE USERPHPが接続に使うMySQLのユーザを作る。名前とパスワードはPHPファイルに書かれているものに合わせている
      GRANT ALL ONそのユーザに、updatetime の中だけを操作する権限を与える（最小権限）
      CREATE TABLE日時（DATETIME型）とIP（文字列）の2列をもつ表を作る

      コメントにある grant … identified by 'password' は古い書き方で、Ubuntu 24.04 のMySQL 8ではエラーになります。そのため「ユーザを作る」と「権限を与える」を分けています。報告のネタになります。

      ユーザ名やパスワードを変える場合は、dateadd.php と dateprint.php の両方にある 'ktajima','password' も同じに書き換えてください。

      12

      PHPの時刻を日本時間にする

      手順書オリジナル（ずれ防止）

      PHPは初期設定のままだと世界標準時（UTC）で時刻を出すので、記録される時刻が日本時間より9時間早くなります。Apache用のPHPの設定ファイルを書き換えます。

      sudo sed -i 's/^;date.timezone =.*/date.timezone = Asia\/Tokyo/' /etc/php/*/apache2/php.ini
grep -n "^date.timezone" /etc/php/*/apache2/php.ini
sudo systemctl restart apache2

      2行目の結果に date.timezone = Asia/Tokyo が出ればOKです。

      あえてこのステップを飛ばして動かし、時刻のずれを確認してから直すと、「詰まった点・原因・対処」がそろった報告になります。

      配布のPHPをサーバに置く

      db_sample.zip（LMS）
      db_sample.zip をダウンロードLMSからでも同じものが取れます。ダウンロードフォルダに保存してください

      ダウンロードした db_sample.zip を解凍して送ります。ここだけはSSHに入っていないPowerShellで実行します（新しいタブを開くと便利です）。

      cd $env:USERPROFILE\Downloads
Expand-Archive .\db_sample.zip -DestinationPath . -Force

      サーバ側で、Webの公開フォルダにコピーします。

      サーバ側で記録を確かめる

      考察用

      ブラウザで見た内容が、本当にデータベースに入っているかを確かめます。

      sudo mysql -e "SELECT * FROM updatetime.clickedtable;"

      Apacheのアクセスログにも、同じIPからのアクセスが残っています。

      sudo tail -n 5 /var/log/apache2/access.log

      行の先頭がアクセス元のIP、続いて日時、"GET /db_sample/dateadd.php" のようにどのページを開いたかが記録されています。DBの記録とログを並べると、「サーバはアクセスしてきた相手のIPを知っている」ことを説明できます。

      15:00の経過報告（2分）の例

      実験ガイダンス「4. 実験の流れ」

      まず、自分のPCで公開鍵ペアを作り、公開鍵をサーバの authorized_keys に登録して、パスワードを使わずに鍵だけでログインできることを確認しました。秘密鍵はサーバに送らずに済むよう、クライアント側で鍵を作りました。

      次に、Apache・PHP・MySQLを導入し、ufwで80番ポートを許可しました。配布されたPHPを使い、ブラウザからのアクセス時刻とクライアントのIPアドレスをデータベースに記録し、一覧表示できることを確認しました。

      詰まった点として、配布コードのコメントにあるGRANT文はMySQL 8では使えない書き方だったため、ユーザ作成と権限付与を分けて実行しました。また、PHPのタイムゾーンがUTCのままだと記録時刻が9時間ずれたため、php.iniでAsia/Tokyoに設定しました。

      実際にできたところ・詰まったところに合わせて変えてください。「詰まった点・原因・対処」の3つがそろうと伝わりやすくなります。
