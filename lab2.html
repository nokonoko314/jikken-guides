      Permission denied (publickey) と出てパスワードを聞かれない場合

      パスワードログインが無効になっています。サーバの前で、sudoが使えるユーザでログインして次を実行します。最後の行が yes になれば戻っています。

      sudo rm -f /etc/ssh/sshd_config.d/00-no-password.conf
sudo systemctl restart ssh

      サーバのIPはDHCPで決まるので、再起動やネットワークの設定変更で変わります。今回も、途中でサーバのIPが変わり、相方のPCが古いIPのまま接続して Connection timed out になりました。

      hostname -I

      サーバの前でこれを実行して、今のIPを確かめます。上のバーの「サーバのIP」と、手順6で作った .ssh\config の HostName の両方を書き換えてください。

      自分のPCで鍵ペアを作る

      補足 スライド「証明書によるログインにする」

      このコマンドは自分のPCのPowerShellでサーバの中で実行すると、変な名前の鍵がサーバにできてしまいます。プロンプトが PS C:\…> になっていることを確かめてから貼り付けてください（下のつまずいたとき）。

      mkdir $env:USERPROFILE\.ssh -Force
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\id_ed25519_{{USER}}

      表示操作
      Enter passphrase (empty for no passphrase):秘密鍵のパスフレーズを入力（スライドの「秘密鍵にパスワードをかけておくとより安全」）。なしなら Enter
      Enter same passphrase again:1回目と同じものを入力
      Overwrite (y/n)?同じ名前の鍵がある。作り直すなら y、今の鍵を使うなら n

      入力中は何も表示されませんが正常です。四角い模様（randomart）が出れば完成です。

      dir $env:USERPROFILE\.ssh
          Directory: C:\Users\あなた\.ssh

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a---          2026/10/13    13:06            411 id_ed25519_{{USER}}
-a---          2026/10/13    13:06             97 id_ed25519_{{USER}}.pub
-a---          2026/10/13    13:02            828 known_hosts
（id_ed25519_{{USER}} と .pub の2つがあれば成功）

      id_ed25519_ユーザ名（秘密鍵）と ….pub（公開鍵）の2つがあればOKです。

      スライドの「サーバ上で鍵を作った場合はきちんとクライアントに転送」は、サーバで作る方法の注意です。自分のPCで作ればこの転送が要らず、秘密鍵がネットワークを通りません。

      つまずいたときPowerShell用のコマンドを、サーバの中で打ってしまった

      一番多かったつまずきです。SSHでサーバに入ったままの画面に、自分のPC用のコマンドを貼り付けると、次のようなエラーになります。

      -bash: cd: :USERPROFILEDownloads: No such file or directory
Expand-Archive: command not found
mkdir: invalid option -- 'F'
Add-Content: command not found
      見分け方プロンプトの例そこで打つもの
      自分のPC（PowerShell）PS C:\Users\…>$env:USERPROFILE、ipconfig、ssh、scp、Expand-Archive
      サーバ（SSHで入った状態）ユーザ名@サーバ名:~$sudo、apt、mysql、hostname -I、chmod

      直し方：exit でサーバから抜けて、プロンプトが PS C:\…> に戻ってから貼り直します。ターミナルの「＋」で新しいタブを開き、「PC用」と「サーバ用」のタブを分けておくと取り違えにくくなります。

      つまずいたときサーバの中で鍵を作ってしまった

      手順2の ssh-keygen をサーバで実行すると、$env:USERPROFILE\ がLinuxでは正しく読めず、ホームフォルダに :USERPROFILE.sshid_ed25519_ユーザ名 という変な名前の鍵ができます。秘密鍵はサーバに置くものではないので、消してから自分のPCで作り直します。

      rm -i ~/:USERPROFILE.sshid_ed25519_*
ls -a ~
      rm: remove regular file '/home/{{USER}}/:USERPROFILE.sshid_ed25519_{{USER}}'? y
rm: remove regular file '/home/{{USER}}/:USERPROFILE.sshid_ed25519_{{USER}}.pub'? y
$ ls -a ~
.  ..  .bash_history  .bash_logout  .bashrc  .cache  .profile  .ssh          ← 変な名前のファイルが消えていれば成功

      rm -i は1つずつ「消しますか？」と聞いてきます。y を入力してから Enter を押さないと消えません。何も入力せずに Enter だけ押すと「消さない」扱いになります。

      公開鍵をサーバに登録する

      補足 スライド「証明書によるログインにする」
      type $env:USERPROFILE\.ssh\id_ed25519_{{USER}}.pub | ssh {{USER}}@{{IP}} "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
      {{USER}}@{{IP}}'s password:          ← ここで最後のパスワード入力
（何も表示されずにプロンプトに戻れば、登録できている）

      聞かれるのはサーバでの自分のパスワードです。何も表示されずに戻れば成功です。

      部分していること
      type ….pub自分のPCにある公開鍵の中身を読み出す
      | ssh …その中身をSSHでサーバへ送る
      cat >> ~/.ssh/authorized_keys受け取った公開鍵をファイルの末尾に追記する
      chmod 700 / 600自分以外が読み書きできないようにする。権限が緩いとsshdが鍵ログインを拒否する

      接続コマンドを短くする（任意）

      補足

      この設定は、このPCだけのもの相方のPCで ssh lab と打っても使えません（下のつまずいたとき）。

      @"

Host lab
    HostName {{IP}}
    User {{USER}}
    IdentityFile ~/.ssh/id_ed25519_{{USER}}
"@ | Add-Content -Encoding ascii $env:USERPROFILE\.ssh\config
      （何も表示されない。ssh lab で入れるようになる）

      これで ssh lab だけで接続できます。IPが変わったら notepad $env:USERPROFILE\.ssh\config で HostName を書き換えます。以下の手順は、このステップを飛ばしても動くように書いています。

      つまずいたとき相方のPCで ssh lab が使えない 
      ssh: Could not resolve hostname lab: \202\273\202\314\202\346…

      後ろの記号は、日本語の「そのようなホストは不明です」が文字化けしたものです。lab という名前は、手順6で自分のPCにだけ登録したものなので、相方のPCでは使えません。相方は、自分のユーザ名と鍵の場所で、自分のPCに同じ設定をするか、ssh 相方のユーザ名@サーバのIP の形で直接つなぎます。

      班員それぞれのユーザを登録する（各自が自分のPCから）

      phpMyAdminを自分のPCのIPからだけ開けるようにする

      スライド「phpMyAdminのインストール」アクセス制限

      班員が2人以上いるときこのコマンドは設定ファイルを丸ごと書き直すので、班員がそれぞれ実行すると、最後に実行した人のIPしか残りません。班員全員のIPを1行にまとめる方法は、下のつまずいたときにあります。

    'deny DBユーザ1 from all',

      スライドの1つ目の方法「userdirモジュール」を使います。ホームの public_html に置いたファイルが、http://IP/~ユーザ名/ で見られるようになります。

      補足：スライドのURL例（http://IP/ユーザ名）のように ~ なしにする

      つまずいたとき個人ページが Forbidden になる（/~ユーザ名/） 
      AH00035: access to /~ユーザ名/ denied (filesystem path '/home/ユーザ名/public_html') because search permissions are missing on a component of the path

      ホームフォルダに chmod 711 がかかっていません。このchmodはユーザごとに必要です。自分のユーザで実行しても、相方のホームには効きません。原因を確かめるときは、次のコマンドが便利です。

      sudo tail -n 3 /var/log/apache2/error.log
      [Tue Oct 13 14:20:31.512330 2026] [core:error] [pid 6120:tid 6125] [client 192.168.0.25:51234] AH00035: access to /~{{USER}}/ denied (filesystem path '/home/{{USER}}/public_html') because search permissions are missing on a component of the path

      つまずいたときURLに入れる名前を間違えた

      http://サーバのIP/~○○/ の ○○ は、Linuxのユーザ名（ホームフォルダの持ち主）です。phpMyAdminのログインに使うDBのユーザ名とは別物です。両者を同じ名前にしておくと迷いません。

      つまずいたとき「Index of /~ユーザ名」と表示された

      エラーではなく、フォルダの中身の一覧です。権限の問題は解決していて、まだ index.php を置いていないので、中身がない一覧が出ています。index.php を置けば、そのページが表示されます。

      補足相方のページを、自分のユーザから代わりに作る

      相方がその場でログインできないときは、sudoで作ってから持ち主を相方に変えます。相方 を相方のLinuxユーザ名に書き換えて実行します。

      sudo chmod 711 /home/相方

sudo chmod 755 /home/相方/public_html
      （何も表示されない）

      chown を忘れると、ファイルの持ち主が root のままになり、相方があとで編集できません。

      PHPの時刻を日本時間にする

      補足

      PHPのタイムゾーン（手順15）を直しても、MariaDBの DEFAULT CURRENT_TIMESTAMP で入れた時刻は、サーバの時計（世界標準時）のままです。PHP側で date('Y-m-d H:i:s') を作って入れると日本時間になります。サーバ全体の時計を日本時間にする方法もあります（sudo timedatectl set-timezone Asia/Tokyo）。

      改良の例使うもの
      新しい記録が上に来るように並べるSQLの ORDER BY time DESC
      IPアドレスごとのアクセス回数を表示するGROUP BY ip と COUNT(*)
      ブラウザの種類も記録する表に列を追加（ALTER TABLE）、$_SERVER['HTTP_USER_AGENT']
      名前とひとことを書き込める掲示板にするHTMLの <form> と $_POST、サンプルと同じ prepare / bindValue
      記録を削除できるようにするDELETE FROM、どの行かを決める主キー（id列）

      入力を受け取るときは、サンプルと同じく prepare でSQLを組み立て（SQLインジェクション対策）、表示するときは htmlspecialchars を通します（XSS対策）。この2つを守ると、Webに公開しても安全なプログラムになります。
