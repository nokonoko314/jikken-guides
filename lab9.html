      クラスとは何か

      スライド「クラス」

      クラスは、変数（データ）と、それを扱うメソッド（機能）をひとまとめにした型です。クラスに属する変数とメソッドを「メンバ」と呼びます。

      アクセス修飾子どこから使えるか
      publicどこからでも
      protected同じパッケージと、継承した子クラスから
      （何も付けない）同じパッケージから
      privateそのクラスの中からだけ

      変数を private にして、メソッドを通してだけ値を変えられるようにすることをカプセル化といいます。スライドの例のように、「1〜5の数しか入れられない」といったチェックを、代入するメソッドの中に書けるのが利点です。

      2

      変数とメソッドを持たせる

      スライド「クラスに要素（メンバ）を持たせよう」〜「要素をまとめて代入／出力」

      NetBeansでは、パッケージを右クリック →「新規」→「Javaクラス」で、クラスのひな型ができます。スライドの例では、名列番号と名前を、まとめて設定するメソッドと、まとめて文字列にするメソッドを作っています。

      public class Seiseki {
    private int number;
    private String name;

    public void setID(int num, String str) {
        name = str;
        number = num;
    }
    public String getString() {
        return number + " " + name;
    }
}

      同じように、4教科の点数を持つ変数と、それをまとめて設定するメソッドを、自分で足します。スライドの「まとめて4教科分データを渡せると良い」は、配列（int[]）で受け取る形などが考えられます。

      スライドの「メソッドが多すぎない？」のとおり、全部の変数に get と set を付けると、private にした意味が薄れます。「まとめて設定する」「設定するタイミングを決める」「出力の機能をクラスに持たせる」のどれで作ったか、その理由を説明できるようにしておくと良いです。

      コンストラクタと toString を作る

      スライド「コンストラクタの追加」「printlnは何を表示するの？」
      もの役割と決まり
      コンストラクタnew Seiseki(2, "Emma") のように、作るときに値を渡して初期化する。名前はクラスと同じで、戻り値を書かない
      toString()System.out.println(オブジェクト) で表示される文字列を決める。@Override を付けて上書きする

      toString を作る前に println(student1) を実行すると、Seiseki@1b6d3586 のような文字が出ます。これは「クラス名＠識別番号」で、すべてのクラスが最初から持っている toString の表示です。スライドの「何と表示されましたか？」はこのことを確かめる問いです。

      複数の学生をまとめて扱う

      スライド「値を入れていこう」「値を取り出す機能」
      入れ物入れる／取り出す特徴
      ArrayList<Seiseki>add ／ get(番号)、拡張for文入れた順に並ぶ（スライドではFIFO）
      Stack<Seiseki>push ／ pop最後に入れたものから出る（LIFO）
      HashMap<String, Seiseki>put(名前, 学生) ／ get("Michael")名前から一発で取り出せる

      自分で作ったクラスも、Integer や String と同じように、これらの入れ物にそのまま入れられます。第6・7回（GUI）の成績検索でも、この形がそのまま使えます。

      6

      継承で教科を増やしたクラスを作る

      スライド「継承によるクラスの拡張」「継承の実装の注意点」

      元のクラス（親クラス）の機能をそのまま受け継いで、変数やメソッドを足した新しいクラス（子クラス）を作ります。書き方は class 子クラス extends 親クラス です。

      注意点（スライドより）どう対処するか
      子クラスから親の private 変数は使えない子クラスから使いたい変数は protected にする。スライドの例で score1 などに直接触れているのは、private ではないから
      コンストラクタは継承されない親に引数つきのコンストラクタしかないときは、子のコンストラクタの最初の行で super(番号, 名前) のように親のコンストラクタを呼ぶ
      継承元は1つだけJavaは単一継承。複数の性質を持たせたいときはインタフェースを使う（手順7）

      追加の教科の点数は「ランダムに追加すればよい」とあるので、new Random().nextInt(101)（0〜100の整数）などで作れます。親クラスの変数として扱えるので、子クラスのオブジェクトを ArrayList<Seiseki> にそのまま入れることもできます（ポリモーフィズム）。

      7

      オーバーライド・抽象クラス・インタフェース

      スライド「オーバーライド」〜「インターフェース」
      仕組み意味この課題での使い道
      オーバーライド親と同じ名前・同じ引数のメソッドを子で定義すると、子のほうが実行される平均点を求めるメソッドを、5教科用に書き直す（スライドの getAverage）
      抽象クラス中身のないメソッド（abstract）を持ち、継承した子が中身を書く。インスタンスは作れない「部屋」を抽象クラスにし、予約の可否を子クラスで決める（追加課題）
      インタフェースメソッドの型だけを決め、implements で実装する。複数実装できる「予約できる（Reservable）」という性質を、会議室にだけ持たせる

      スライドのインタフェースの例にある const int I = 1; は、Javaでは書けません（const はJavaのキーワードとして予約されているだけで使えない）。インタフェースの定数は int I = 1; と書けば、自動的に定数になります。また increment() は int を返す宣言なので、実装側に return が必要です。資料どおりに打ってエラーになったら、この2点を確認してください。
