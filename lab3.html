    ヒューリスティックサーチの応用

    実施日2026年10月20日（火）
    レポートレポート①　10/27（火）9:00 締切
    この回でやること迷路をグラフ（点と接続）としてデータにし、ゴールまでのマンハッタン距離が小さい点から調べるヒューリスティック検索で、SからGまでの経路を求める。OPEN・CLOSEDリストの推移と経路を表示する。

      迷路をグラフとして読み取る

      スライド「迷路のグラフ化方法」「迷路のデータ」

      迷路の交差点・曲がり角・行き止まりを「点（ノード）」、点と点をつなぐ通路を「線（リンク）」として扱います。これで迷路がグラフになり、探索の問題として解けるようになります。

      点座標点座標点座標
      S（スタート）(0,0)A(2,0)B(5,0)
      C(0,2)D(2,2)E(7,2)
      F(0,4)H(2,4)I(4,4)
      G（ゴール）(7,4)J(2,6)K(6,6)
      L(0,7)M(2,7)N(7,7)
      Fの座標に注意スライド4枚目では F(0,4)、9枚目では F(4,0) になっています。10枚目の木構造ではFがCの先にあるので、F(0,4) が正しいと考えられます。迷ったら先生に確認してください。

      やること：接続情報を書き出す

      スライドの迷路の図を見て、それぞれの点がどの点とつながっているかを、自分で表にします。スライドの木構造（10枚目）から、たとえば次のつながりが読み取れます。

      • S は A と C につながっている
      • C の先に F と D、A の先に B、B の先に E がある

      通路は両方向に通れるので、「S–A」と書いたら、A側にも S を入れておくと探索が書きやすくなります（無向グラフ）。表は紙に書いておくと、レポートの「実験内容」の図にもそのまま使えます。

      3

      データ構造を設計する

      スライド「本日の作業内容」迷路を定義する

      スライドで「データ構造をどう設計するとよいか考えましょう」とされている部分です。最低限、次の情報を持てるようにします。

      持たせる情報考え方
      点の名前・X座標・Y座標1つの点を1つのオブジェクト（クラス）にまとめると扱いやすい
      つながっている点の一覧点ごとに「隣の点のリスト」を持たせる（隣接リスト）。点の数が少ないので、2次元配列（隣接行列）でもよい
      スタートとゴールどの点がスタート・ゴールかを、迷路全体を表すクラスで持つ
      どこから来たか経路を表示するために必要。点をOPENに入れるとき「どの点から来たか（親）」を覚えておく

      点を表すクラスの「入れ物」だけを書くと、たとえば次のような形になります（中身の処理は自分で考えます）。

      class Node {
    String name;                       // 点の名前（"S" など）
    int x, y;                          // 座標
    List<Node> links = new ArrayList<>(); // つながっている点
    Node parent;                       // どの点から来たか（経路の復元用）
}

      名前から点を取り出したいときは Map<String, Node> を使うと便利です。隣接リストと隣接行列のどちらを選んだか、その理由は、レポートの「実験内容」で説明できる設計のポイントになります。

      4

      評価関数を決める（マンハッタン距離）

      スライド「本日の課題の実施方法」「マンハッタン距離とは」

      ヒューリスティックサーチでは、「この点はゴールに近そうか」を数値にして、良さそうな点から先に調べます。今回はその数値（評価関数）に、ゴールまでのマンハッタン距離を使います。

      マンハッタン距離点 (x1, y1) と (x2, y2) の距離 ＝ |x1 − x2| ＋ |y1 − y2|　（横に進む量＋縦に進む量）

      スライドに載っている値で、自分の計算が合っているか確かめます。

      点座標Gまでの距離
      S(0,0)|7−0|＋|4−0| ＝ 11
      A(2,0)9
      B(5,0)6
      C(0,2)9
      D(2,2)7

      Javaでは絶対値を Math.abs() で求めます。残りの点の距離は、自分で計算して表に足しておくと、手順5の手作業の確認に使えます。

      5

      アルゴリズムを手で追ってみる

      スライド「ヒューリスティックサーチとは」「具体的な例」「アルゴリズム」

      いきなりコードを書く前に、紙の上でOPENとCLOSEDの変化を追うと、プログラムの完成形がはっきりします。答え合わせの材料にもなります。

      用語意味
      OPENこれから調べる予定の点の一覧。評価値（距離）が小さい順に並べておく
      CLOSED調べ終わった点の一覧。同じ点を二度調べないために使う
      展開点 u から行ける点を、すべて洗い出すこと

      スライドのアルゴリズム（要約）

      1. S を OPEN に入れる。CLOSED は空
      2. OPEN が空なら終了（経路なし）
      3. OPEN の先頭 u を取り出して CLOSED に入れる
      4. u がゴールなら終了（経路あり）
      5. u を展開して、行ける点の集合 Vu を求める
      6. Vu が空なら 2 へ戻る
      7. Vu から OPEN・CLOSED にすでにある点を除き、残りを OPEN に追加して、距離の小さい順に並べ直す
      8. 2 へ戻る

      スライドの例（最初の3回）

      回OPENCLOSED
      0S[11]（空）
      1A[9], C[9]S[11]
      2B[6], D[7], C[9]A[9], S[11]
      3〜ここから先を、手順2で作った接続表を見ながら自分で続ける

      A[9] と C[9] のように評価値が同じ点が出たとき、どちらを先にするかで探索の順番が変わります。自分のプログラムではどうなるか（並べ直しのルール）を決めておくと、手作業とプログラムの結果を比べやすくなります。

      6

      Javaで書く

      スライド「アルゴリズム」「補足 ラムダ式と並び替え」

      手順5のアルゴリズムの各行を、Javaのどの道具で書けるかの対応表です。

      アルゴリズム使えるもの
      OPEN・CLOSEDArrayList<Node>
      OPEN の先頭を取り出すopen.remove(0)
      2〜8 の繰り返しwhile (!open.isEmpty()) { … }
      すでに OPEN・CLOSED にあるかopen.contains(v)、closed.contains(v)
      距離の小さい順に並べ直すopen.sort(…) または Collections.sort(open, …)

      並び替えの書き方（スライドの補足）

      スライドにあるとおり、並べ方は3通りの書き方ができます。一番短いのはラムダ式です。点の距離を返すメソッド（ここでは仮に h()）を用意しておくと、次のように書けます。

      open.sort((a, b) -> a.h() - b.h());       // ラムダ式
open.sort(Comparator.comparingInt(Node::h)); // さらに短い書き方

      Comparatorクラスを別に作る「古風な方法」や、匿名クラスを使う方法でも、結果は同じです。どれを使ったか、なぜそれを選んだかは、レポートの「使用言語や環境」「原理」で触れられます。

      つまずきやすい点

      • 同じ点を何度も OPEN に入れてしまう：手順7の「OPEN・CLOSEDにある点は除く」を忘れると、行ったり来たりして終わらなくなります
      • for文で回しているリストを、その中で変更する：ConcurrentModificationException が出ます。追加する点を、いったん別のリストに集めてから OPEN に足すと安全です
      • 親（parent）の記録：点を OPEN に入れるときに、「u から来た」と記録しておかないと、手順7で経路を表示できません
      7

      経路とOPEN・CLOSEDの推移を表示する

      スライド「本日の作業内容」得られた経路／OPEN・CLOSEDの推移

      基本課題では、次の2つを表示する必要があります。

      表示するものヒント
      OPEN・CLOSEDの推移繰り返しの1回ごとに、OPEN と CLOSED の中身を「名前[距離]」の形で1行ずつ出力する。手順5の表と同じ形にすると、手作業の結果と見比べられる
      得られた経路ゴールに着いたら、ゴールから parent を順にたどってSまで戻り、その順番を逆にして表示する（Collections.reverse()）

      表示はたとえば、次のような形にすると読みやすくなります（形式は自由です）。

      OPEN: [S[11]]                  CLOSED: []
OPEN: [A[9], C[9]]             CLOSED: [S[11]]
OPEN: [B[6], D[7], C[9]]       CLOSED: [S[11], A[9]]
…
経路: S -> … -> G

      Nodeクラスに toString() を書いて「名前[距離]」を返すようにすると、System.out.println(open) だけでリスト全体がこの形で表示されます。この出力は、そのままレポートの「実行結果」に載せられます。

      発展課題の考え方

      スライド「本日の作業内容」発展課題／「挑戦的課題における検討事項」

      採点基準では、発展課題に取り組んで考察すると「考察」の最高点（4点）に届きます。プログラムを作らなくても、分析して書くだけで評価されるものもあります。

      発展課題考え方の手がかり
      最短経路にならない理由今の評価値は「ゴールまでの見込み」だけで、「ここまでに歩いた距離」を見ていません。ゴールに近く見えても、実際は遠回りになる道を選ぶことがあります。両方を足して評価する方法（A*探索）と比べると説明しやすいです
      探索方法を変えて、調べた点の数を比べるOPEN の扱い方を変えるだけで探索方法が変わります。並べ替えずに後ろから取る（スタック）と深さ優先、前から取る（キュー）と幅優先、展開した中で一番良い点だけを残すと山登り法です。CLOSED に入った点の数を数えて表にすると比較できます
      迷路をファイルから読み込むスライドの表（点の名前・X・Y・種類・接続数・接続先）をそのまま1行1点のテキストにすると簡単です。Files.readAllLines() で行を読み、split("\t") や split(",") で分けます。点を全部作ってから、2周目で接続をつなぐと、まだ作っていない点を参照する問題を避けられます
      新しい迷路で検証する「最短経路にならない例」をわざと作れると、1つ目の発展課題の説明にそのまま使えます。行き止まりの多い迷路、ゴールが近くに見えて遠回りが必要な迷路などを試します

      スライドの後半にあるオセロのAIの例も、「良さそうな手を数値で評価して選ぶ」という同じ考え方です。角に重みを付けるように、評価関数の工夫で結果が変わる点を考察に使えます。

      うまくいかないとき

      症状原因と対処
      'java' は認識されていませんJDKが入っていない、またはPowerShellを開き直していない（手順1）
      探索が終わらないOPEN・CLOSEDにある点を除いていない。同じ点を行き来している
      ConcurrentModificationExceptionfor文で回しているリストを、その中で追加・削除している。別のリストに集めてからまとめて足す
      経路を表示すると NullPointerExceptionparent を記録していない点がある。OPENに入れるときに必ず記録する
      並び順が手作業と違う評価値が同じ点の順番のルールが違う。並べ替えの決まりを確認する
      経路が見つからない接続情報の書き漏れ。特に、片方向にしかつないでいないことが多い
